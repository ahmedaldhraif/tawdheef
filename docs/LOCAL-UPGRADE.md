# Local upgrade checks

Keep the original private data directory. Back up SQLite with its consistent online backup API or stop the app before copying the database and its WAL; copying only a live main database file is insufficient. Keep source changes and private configuration backups outside Git and release archives. Do not reset directories, settings or client configuration to install an update.

Compare directory IDs and counts, confirmed snapshot totals, saved settings and run history before and after opening a disposable migration copy. New defaults are additive. Native connection ownership does not delete compatibility credentials, change their accounts or prove that the actual client has signed in.

The default Native app loads no provider sessions or managed assistant runner. Existing app-owned vacancy rules keep their scope and results. Their API states `executionOwner:local-adapters` and `runnable:false` in Native mode. Recurring application permission is paused at restart; a new explicit Run is required for unfinished submissions. Native Updates uses the actual client's own selected read-only tools and supported local schedule, with dated reported status and real check evidence kept separately.

Test profile work independently of applications; a previously applied company can still need a career profile. Verify shared-company duplicate protection across packs, unknown submission recovery, the restricted monitoring catalog, keyboard and unsaved-edit behavior, paginated run history and hidden-tab polling. Automated checks use synthetic accounts and receipts. An upgrade check never sends an email, applies, creates a real profile, writes a calendar event or enables a schedule.

After stopping the old process, apply reviewed source/build files only. Preserve unrelated local work and check for concurrent edits before overwriting a file. Restart on the same loopback address and private path, compare the live state with the baseline, and verify project-only Codex/Claude configurations without modifying global settings or account credentials.

An existing source checkout can instead keep a reviewed prebuilt app alongside its ongoing development work. The private `.tawdheef-setup/active-install.json` pointer uses `{format:1,appRoot,dataDir,workspace,port}` with absolute paths and an existing private data folder. Ordinary source start/background/CLI/MCP entry points validate the package manifest, platform, architecture, bundled runtime and exact entry point before forwarding. They retain the actual client's identity and permissions. The packaged app never forwards again. Invalid pointers fail with an actionable error; explicitly different data/workspace/port requests remain isolated source invocations. Stop the old owned process before activating a pointer. This is a local launch choice, not an automatic downloader or updater.
