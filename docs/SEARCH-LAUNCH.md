# Search and public launch

Tawdheef is a personal open-source project by Ahmed AlDhraif. A licence or
policy file does not certify GitHub compliance or guarantee a search listing.

## Positioning and first use

Use the approved category **Tawdheef — Auto Job Apply & Application Tracker**
in descriptive titles and repository context. The hero reads **Auto-apply to
jobs. Track your applications.** Its supporting line is **Free, open-source
software for you and your ChatGPT or Claude agent.** This is an owner-approved
message, not evidence of higher conversion or search ranking.

The path is GitHub release → local agent-assisted setup → free Tabbio CV or
existing account → connect and verify → choose targets → explicitly start Run.
The hero links to setup; actual downloads go directly to official GitHub
Release assets, with a clone alternative. Use the current
[v0.1.1 preview](https://github.com/ahmedaldhraif/tawdheef/releases/tag/v0.1.1)
or `/releases`, not `/releases/latest` while the release is a prerelease.
Coordinate future version links with the release owner.

State the operational limits in setup and workflow help: local Codex or Claude
Code is required, provider accounts have their own permissions and possible
costs, and sign-ins, CAPTCHA, provider approval and LinkedIn steps may need
the person. Directory browsing/manual tracking works without Tabbio; Run needs
a connected Tabbio CV. Avoid guaranteed, unattended or all-sites claims.

Country pages should point to their real public pack and its sources. Invite
any country through GitHub issues and pull requests. Do not imply community
contributions already exist or turn research records into vacancy counts.

## GitHub

- Publish only the reviewed public source allowlist. Keep `.local`, raw working
  research, credentials, CVs, mailbox contents and tracking records excluded.
- Retain MIT copyright and licence notices, source provenance and third-party
  notices. Contributors must have the rights to submit their contributions.
- Keep corrections and removals available. Enable private vulnerability reporting.
- Moderate project participation under the code of conduct. GitHub's own
  acceptable-use rules still apply. The project does not run applications or
  unsolicited outreach through GitHub Actions.

## Website

- Deploy only `site-dist`, never the local tracker or its data directory.
- Production pages have canonical URLs, a sitemap, crawlable links, descriptive
  headings and useful public content. Local preview routes remain non-indexable.
- Publish actual available packs with dates, counts, sources and gaps. Do not
  generate empty country pages, fabricated vacancies or pages solely for keywords.
- Directory metadata describes datasets, not active job postings. Do not add
  `JobPosting` markup to company lists without actual eligible job content.
- The production `robots.txt` permits crawling. After domain deployment, verify
  the site in Search Console and submit the sitemap. No Search Console action
  or indexing is implied by a local build or GitHub publication.
- Google states that its AI search features use ordinary SEO fundamentals;
  there is no special AI schema requirement. `llms.txt` is a convenience for
  readers, not proof that an agent or search service will use the site.

## Limits

Google decides whether to crawl, index or display a page. GitHub and connected
providers enforce their own terms. MIT disclaimers and project policies do not
eliminate every legal risk. The maintainer should obtain jurisdiction-specific
legal advice before relying on them for liability, privacy or data-reuse questions.
