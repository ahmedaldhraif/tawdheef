# Tawdheef 0.2.0 beta — Native local desktop preview

**Unsigned beta:** Windows downloads are not publisher-signed; Mac downloads are not signed or notarized. Operating systems may warn or block opening them. Keep OS protections enabled. Signing is a separate publisher step, not a requirement for keeping your tracking local.

Tawdheef runs its interface and tracking database on your computer. Your actual Codex or Claude Code client owns its CV, email, calendar, browser/computer and password-manager connections. That client and connected services can communicate online under your permissions. You do not need a developer account or signing certificate to use Tawdheef.

Use the attached package and smoke reports to identify the exact source commit, archive checksum, OS and architecture. Preparing these notes does not publish a release or establish successful live employer/account actions.

## Changes

- One client-owned setup request checks the intended mailbox, readable CV, upload file and browser access together. Existing accounts and preferences are reused; optional calendar/password-manager reports do not block unrelated work.
- Clear Needs you checkpoints and explicit single-company Resume retain the original actions and inspect uncertain submissions before continuing.
- Compact Assistant choices, header Back, explicit clipboard handoffs and on-demand connection details. Keyboard selection and accepted settings survive temporary refresh failures.
- Node 26.13.1 and Vite 8.3.8, with a prebuilt tracker-only interface. Ordinary downloads contain no bundled npm, browser engine or app-managed mail/calendar SDKs.
- Faster SQLite filtering, paging and compact progress snapshots. Large company research payloads stay in the database when the interface only needs outcome counts; archived evidence and revision semantics remain intact.
- One visibility-aware run reader instead of repeated screen/dialog polling.
- Website search restores keyboard focus correctly in Safari after Close, Escape or clicking outside, in English and Arabic.
- Native launchers, writable data and assistant workspaces outside the installed app, and explicit login startup on supported OSs.
- Native-client connections only: Codex or Claude Code owns the CV, mailbox, calendar, browser/computer tools and password-manager access. Tawdheef keeps local guidance, scoped authority and recorded results.
- Project-only MCP setup for both clients, with direct Tabbio MCP included only when selected. Client-reported external access is dated and separate from actual local tracker tool-use receipts.
- Separate account/profile/CV/application outcomes, directory snapshots and explicit run choices.
- A copied run request continues in the existing client chat. Compact, claim-scoped queue tools preserve the selected actions and company scope without another model subprocess. Unknown submissions retain their original intents and need inspection before retry.
- A short Connections list for Assistant, Tabbio CV, Email, Calendar, Browser & computer use and Passwords. Passwords for career sites stay in the supported browser or password manager.
- App-owned provider adapters, assistant subprocess queue and model diagnostic are retired. External connections belong to the actual client; historical settings and records remain preserved.
- Read-only job discovery and changed-job review, with current CV/preference evidence for matching and clear Needs you outcomes. Discovery does not authorize applications, profiles or CV sharing.
- Inspected historical-submission recovery preserves the original intent and never sends again. Old email intents without saved original mailbox provenance remain unresolved rather than being assigned to the current account.
- Local native-client monitoring for selected careers sources, existing profiles, tracked email threads and selected calendar events. Updates retain source evidence; incomplete checks remain unknown. Settings prepares a request for the native client, without pretending a copied request created a schedule.
- Bounded local records and original PDF/DOCX staging for explicitly authorized uploads. Native CV facts are read directly through the client's own connection; Tawdheef does not duplicate the native CV cache.

## Setup and updates

Open Connections and choose Codex or Claude Code, then paste Copy setup request into that existing client. Reuse its supported connections and normal permissions. Tawdheef's native screen does not require a separate CLI, model test or provider login. Unsupported tools, sign-in and identity prompts produce Needs you; setup never guarantees quotas, account eligibility or successful job submissions.

Native app data defaults to your user application-data directory. Explicit `APPLY_TRACKER_DATA` and adjacent existing `.local` data are preserved. Nothing migrates automatically. Stop the app, back up private data, extract updates separately and keep the same data path/port before removing an old installation. Assistant configuration and skills live in the writable workspace; custom edits remain protected.

Optional monitoring uses a dedicated project and the selected Codex or Claude Code client's supported local schedule. The computer, tracker and selected client must be available. It does not start applications, create profiles, upload/share CVs, send messages or write calendar events. See [Monitoring](../MONITORING.md) for setup and recorded-status limits.
