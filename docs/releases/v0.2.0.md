# Tawdheef 0.2.0 — local desktop preview

Tawdheef runs its interface and tracking database on your computer. Your chosen Codex or Claude Code client and connected CV/email services still communicate online. You do not need a developer account or signing certificate to use Tawdheef.

## Downloads

Choose the ZIP for Windows x64/ARM64, Mac Intel/Apple Silicon, or Linux x64/ARM64. Extract the complete folder. Windows opens `Tawdheef.exe`; Mac opens `Tawdheef.app`; Linux uses `start-tawdheef.sh`. Each package includes Node 26.13.1 and the prebuilt interface. The interface opens in your normal browser, with no first-launch build or separate Node installation.

Native launchers are small OS executables around the local browser app; this release does not introduce a native UI toolkit. Mac packages require macOS 13.5 or newer. Windows 11 is recommended; OS/architecture evidence is in the attached smoke receipts. Linux needs a compatible glibc runtime and libatomic. Source users can still use patched Node 24 or Node 26.

**Unsigned preview packages can trigger OS publisher/security warnings.** An unsigned package is not a signed or notarized distribution. Do not disable system security to bypass a block. The source edition remains available; publisher signing is a separate optional distribution process. A verified signed download must have matching signing and exact-archive smoke receipts.

## Changes

- Vite 8.3.8, a prebuilt tracker-only interface and optional integrations installed only when selected.
- Faster SQLite list queries and incremental edits, with shared filter, evidence, count and revision semantics retained.
- One visibility-aware run reader instead of repeated screen/dialog polling.
- Native launchers, writable data and assistant workspaces outside the installed app, and explicit login startup on supported OSs.
- Codex/Claude discovery, safe command compatibility checks, real local MCP/browser readiness checks and ownership-aware project setup with backups.
- Separate account/profile/CV/application outcomes, directory snapshots and explicit run choices.
- Provider authentication/access failures stop the queue with an actionable reason, without treating them as company rejections.

## Setup and updates

Open Connections and choose Codex or Claude Code, then use Copy setup request. Each client needs its own working installation, account and provider access. Setup checks local configuration/authentication and tools; it does not guarantee model access, quotas, account eligibility or successful job submissions.

Native app data defaults to your user application-data directory. Explicit `APPLY_TRACKER_DATA` and adjacent existing `.local` data are preserved. Nothing migrates automatically. Stop the app, back up private data, extract updates separately and keep the same data path/port before removing an old installation. Assistant configuration and skills live in the writable workspace; custom edits remain protected.

## Verification

The release pipeline builds on each target OS/architecture and checks the exact extracted ZIP through its native launcher, bundled runtime, repeated startup, external data/workspace setup and real stdio MCP discovery. Backend, browser and synthetic performance receipts have separate scope. Read the attached reports for the exact commit, target and result; no fixture or local timing proves live account access, production applications or field performance.

Source and app archives include checksums. Private tracking, credentials, actual client configuration and local verification data are excluded. These downloads are a public preview.
