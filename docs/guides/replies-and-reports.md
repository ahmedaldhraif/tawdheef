# Track replies and new opportunities

Your actual client reads external sources. Tawdheef saves selected monitoring scope and recorded evidence.

## Check progress now

Ask your agent to inspect only tracked application threads tied to saved submissions, using the original mailbox. Record real changes and next actions. A failed read is not a rejection.

> Review replies for my tracked submissions and summarize new evidence and next actions. Save a local report. Do not send follow-ups or start applications.

A local report is not an email. Delivery needs a separate explicit request and the client's own mail tools.

## Add a schedule when you want one

Open **Monitoring**. Choose sources, frequency, time zone and company scope, then **Copy schedule request**. Paste it into the supported selected desktop client. That client owns its local task; saving settings or copying the request does not create it.

A reported task ID is metadata, not execution proof. Dated check results are separate evidence. The computer, client and tracker must be available. Missing access stays Needs you.

## Monitor new jobs {#monitor-new-jobs}

Choose matching-job sources and companies. Your client reads current careers pages or supported feeds and compares new jobs with your real CV and preferences. Existing profiles, tracked reply threads and explicitly selected calendars can also be monitored read-only.

Monitoring never applies, creates/edits profiles, uploads/shares CVs, sends messages, operates passwords or changes calendar events. Review a job and start a separate explicit Run to act. Native mode does not run older app-owned recurring-application rules.

## Expected result

Dated source checks, supported changes and actionable failures. Unknown results remain unknown. [Monitoring details](https://github.com/ahmedaldhraif/tawdheef-auto-apply-jobs/blob/main/docs/MONITORING.md).
