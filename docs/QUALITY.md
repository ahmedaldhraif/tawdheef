# Practical interface and agent review

The complete 19-skill [Emil Kowalski collection](https://github.com/emilkowalski/skills) is installed as project development resources for Codex and Claude Code. Source paths and content hashes are in `skills-lock.json`; the upstream MIT license is in `.agents/skills/UPSTREAM-LICENSE`. These files do not add runtime dependencies or browser code. Agents load the applicable guidance only when changing the corresponding part of the product.

The web design, mobile, animation review/removal/performance, worst-case data and library-selection guidance informed this pass. The interface keeps its current one-screen layout and original provider marks. Swift and Expo guidance is available for work in those frameworks. Prototype comparisons, gestures, choreographed entrances and new animation libraries were unnecessary for this table-based application. Existing user decisions remain in `DESIGN.md`; this pass does not invent new user taste rules.

| Before | After | Why |
| --- | --- | --- |
| Email, CV and AI controls competed in the header | One Connections entry with grouped provider rows and original local logos | Match familiar account settings and preserve table space |
| Technical connection settings led setup | Provider sign-in first; OAuth registration/import and alternate CLI/MCP choices in details | Keep the common path clear |
| Return from provider settings could lose the user's place | Restore the provider row on Back and the stable Connections trigger on close | Preserve keyboard context |
| Mobile fields used small text and some controls depended on hover | 16px mobile fields, 44px touch actions, visible touch row controls and precise-pointer hover rules | Avoid input zoom and hidden actions |
| Nested scrolling and fixed viewport heights | Contained scrolling, dynamic viewport heights and safe-area spacing | Keep dialogs usable around mobile browser chrome and keyboards |
| Undo expired while reading or using the notification | Pause dismissal while hovered, focused or the document is hidden | Preserve the chance to recover an edit |
| Every 100-row screen refresh included the original source-field bulk | Summary response omits only `sourceFields`; details and default API retain the full original record | The seed payload fell from 294,578 to 72,568 JSON bytes (75.4%); identities, revisions, notes and contacts remain |
| Motion could be added merely for polish | Table, tabs and keyboard actions stay instant; loading indicators respect reduced motion | Repeated work should respond immediately |
| A setup reminder and separate checklist repeated Connections | Provider rows, assistant choice and Check connections in the existing Connections panel; setup request available to copy | Keep account setup in one familiar place |
| Installed clients and saved connections could look ready | Explicit assistant sign-in and CV-read checks with actionable failures | Report what was actually verified |
| Optional connections could feel like requirements | Email and calendar keep their familiar provider rows and remain optional; schedules and reports share the top Settings gear | Only configure the workflow the person wants |
| Run could only use the whole remaining list or a manual selection | City and company-type filters live above the table; search, status and checked rows narrow the same Run scope across every page | See the exact companies before starting |
| Accounts and CV uploads were hidden behind application history | Optional Progress column, preserved milestone history and separate report totals | Show useful work even when no vacancy was applied for |
| Long dialogs could push final actions below the visible area | Run, Save and Cancel stay in their dialog footers while content scrolls | Keep the final action available on small screens |
| Location search looked like another hidden filter | Visible city search, explicit selections and removable chosen locations | Make searching and selecting different, understandable steps |
| A free-text request left application and future-opportunity intent ambiguous | Explicit matching-job, career-profile and CV-email choices, preserved through CLI/MCP and provider receipts | Keep the person's choices explicit |
| Run repeated agent instructions, helper paragraphs and the full generated prompt | A count, three short choices, optional note and Run; rules remain in agent documentation and the runtime prompt | Show only what the person needs to decide |
| Connections repeated what each provider does and displayed setup prompts and schemas | Provider rows, real status and direct sign-in/check actions; Copy setup request keeps the instructions off screen | Make account setup easy to scan without removing usable credentials or recovery |
| Settings explained implementation details around every control | Reply/report schedules, concise last-check status and collapsed Preferences | Keep visible controls focused on decisions |
| Profile work looked secondary to applications | Matching jobs and career profiles are selected in the screen's Run, with separate recorded outcomes and CV email optional | Explain that completing a career profile is useful even when no suitable vacancy is open |
| Outcomes were scattered across company history and reports | One quiet row for Applications sent, Career profiles and Emails sent, with All time/This week and clickable records | Make useful progress visible without adding charts or a second dashboard |
| CV-share company counts could be mistaken for the number of emails | Count confirmed message receipts across applications and CV-only sends, deduplicate receipts and disclose historical missing receipts | Keep email totals honest and separate from unique-company profile counts |
| Loading or a stale request could show another directory's totals | Keep requests tied to directory and period, show unavailable/loading states, and preserve keyboard focus | Make directory switches and failure recovery predictable |
| Working state needed a clear visual cue | A graphite ت with a small code chevron and CSS sheen only during an owned company attempt; static for hidden tabs and reduced motion | Make real activity visible without distracting from progress |

The standard agent catalog has 44 tools (run `npm run tools:catalog` for the current schemas), including the connection readiness check and directory snapshot shared with the screen. Compact company pages retain source type, location and recorded progress; full source evidence is read on demand. Provider libraries are imported on provider use, not during ordinary record-tool startup. Run filters, progress display and the directory snapshot add no runtime dependencies.

Validation uses real local HTTP/stdio servers, isolated databases, mocked provider transports, browser checks and a fresh copy installed from the lockfile. It does not establish live OAuth permissions, successful email delivery or calendar writes, physical iOS behavior, or universal AI-client compatibility. Each user signs in to their own services locally.

Snapshot implementation verification: 244 automated tests and 80 browser checks passed, including directory scope, archived history, receipt deduplication, calendar-week/DST boundaries, stale requests, retry, pagination, keyboard focus, and narrow English/Arabic layouts. A real CLI command and stdio MCP call returned the same isolated fixture totals and records as the screen. Build and release checks passed with 44 published tool schemas. Provider sends were mocked; no real application or email was sent. Older email receipts without mailbox provenance remain conservatively unnamespaced; missing message receipts are disclosed rather than invented.
