# Directory data and contributions

Directory packs are dated public research. They include employers, recruitment agencies, job boards, portals and programmes; these roles are not interchangeable. Inclusion does not establish a vacancy, tested application route, ownership, nationality eligibility, permission to automate or an endorsement.

The initial research is by Ahmed AlDhraif. Contributions from any country are welcome, but an entry is not independently verified merely because someone submitted it or it appears in a pack.

## Sources and reuse rights

Keep source IDs, actual link destinations, dates, attribution, source roles, original evidence and missing-data notes. Read each pack's manifest and source-specific licence notes before reusing it. Do not assume that material is freely reusable merely because it is public or an API can return it.

Contributor-owned original curation, notes and other copyrightable elements are offered under the project's MIT licence unless an explicit file or source notice states a different licence. A contributor can only grant rights they have. The project's licence does not grant rights to underlying third-party websites, copied text, databases, personal information, logos or source material. Retain any separate attribution and reuse requirements; flag uncertain rights for review.

Do not contribute unlicensed bulk copies, scraped private-person contact lists, applicant information, CVs or private tracking exports. Use published organisation-level recruitment routes and only the public facts needed for the directory. Never infer emails, ownership or eligibility. If public evidence contains unnecessary personal information or restricted material, exclude it or propose a limited reference instead of copying it into the pack.

## Corrections and removal

For an ordinary correction or removal request, open a **Directory data** issue with the country/pack, record ID or public URL, what needs changing and supporting evidence. You do not need to publish sensitive details to ask for review.

If the concern itself would expose private information, do not post it publicly. Use the repository's private vulnerability-reporting option if enabled, or ask for a private route without disclosing the material. See [SECURITY.md](../../SECURITY.md). Review and removal are not instant or guaranteed; distributed copies, forks and search caches may remain outside the maintainer's control.

The original 772-record UAE snapshot from 10 November 2026 remains a historical evidence baseline. Correct current records in the reviewed public pack source, retaining stable IDs and a record of changes. Preservation of provenance does not override a valid privacy or rights concern: report it for review rather than copying harmful material again.

See [the contribution guide](../DIRECTORY-CONTRIBUTING.md) for `pack.json`, public `source.json` and validation. Public evidence updates must not overwrite a user's application statuses, notes, receipts or private records.

These are [project-policy drafts](PROJECT.md#draft-status-and-sources), not a guarantee that every source has been legally cleared or is accurate today.
